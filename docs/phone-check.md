# 휴대폰에서 한 화면 자동 계산 사용하기

v0.3.0의 한 화면 자동 계산은 실제 갤럭시에서 아직 확인하지 않았습니다. 이전 방식은 사용자 사진으로 바닥 지정 뒤 천장 단계 진입까지만 확인했습니다. 높이 정확도는 **미검증**입니다.

## 앱에서 할 동작

1. 휴대폰의 **Chrome 앱**을 직접 여세요.
2. 주소창에 **https://ruy911-png.github.io/galaxy-height-check/** 를 붙여 넣고 새로고침하세요. **v0.3.0**을 확인하세요.
3. **높이 측정 시작**을 누르고 권한을 허용하세요.
4. 가구가 가리지 않는 벽을 향해 휴대폰을 듭니다. **위 표시가 실제 천장에, 아래 표시가 발을 딛는 실제 바닥에** 동시에 오도록 구도를 잡으세요. 편하게 서거나 앉아도 됩니다.
5. 두 곳의 표면 인식과 높이가 안정되면 약 1초 뒤 **참고 높이**가 자동으로 표시됩니다. 바닥·천장 지정 버튼은 누르지 않습니다.
6. **다시 읽기**를 누르면 값을 지우고 다시 계산합니다. **종료**를 누르면 카메라를 닫습니다. 현재 자동 값은 별도로 저장하지 않습니다.

설명과 구도 그림은 앱 안에도 있습니다. 뒤로 이동할 필요가 있으면 먼저 화면에서 눈을 떼고 안전한 공간인지 확인하세요. 의자나 침대에 올라갈 필요가 없습니다. 좁은 방에서 바닥·천장을 동시에 담을 수 없으면 이 방식으로는 측정할 수 없습니다. 휴대폰을 접었다 펴거나 방향을 크게 바꾼 뒤에는 새 표면 인식을 기다리세요.

## 문·벽·창 쪽을 고르는 방법

빈방일 필요는 없고 가구를 치울 필요도 없습니다. 두 표시가 모두 실제 바닥·천장에 놓이는 벽 쪽을 고르세요.

| 위치 | 사용할 부분 | 잘못 읽을 수 있는 부분 |
| --- | --- | --- |
| 벽 | 벽 위쪽 천장과 아래쪽 바닥 | 벽 자체는 수직이므로 높이 계산용 면이 아님 |
| 문 쪽 | 문 위의 실제 천장과 방 안쪽 바닥 | 문틀의 수평 턱을 천장으로 잘못 읽을 수 있음 |
| 창가 | 유리를 피한 실내 천장과 바닥 | 유리 반사·창틀·커튼·역광으로 실패할 수 있음 |
| 침대 주변 | 가구 옆의 드러난 바닥과 실제 천장 | 침대 윗면은 실제 바닥과 자동 구분되지 않음 |

앱은 문·창 크기를 기준자로 사용하지 않습니다. 두 위치를 동시에 읽는 것이 자동이며, 사물의 종류까지 자동으로 식별하는 것은 아닙니다. 표시가 가구나 문틀에 있으면 나온 높이를 방 높이로 사용하지 마세요. 인식 실패 때는 이전 좌표나 임의의 값으로 대신 계산하지 않습니다.

확인할 내용은 **두 표시가 실제 면에 놓이는지 / 숫자가 자동으로 나오는지 / 화면의 오류 문구**입니다. 실제 측정값을 얻은 뒤 [5회 기록표](accuracy-check.md)로 줄자와 비교합니다.

## 공식 표면 인식 예제 — 문제를 구분할 때만 사용

아래는 **Immersive Web의 공식 표면 인식 예제**입니다. 자체 앱 확인과 다른 검사이므로, 앱이 잘 열리면 이 예제를 반복할 필요는 없습니다. 예제 성공만으로 높이 정확도를 판단하지 않습니다.

1. 휴대폰 홈 화면에서 **Chrome 앱을 직접** 여세요. 이 대화의 링크를 누르면 앱 내부 창으로 다시 열릴 수 있으므로, Chrome 주소창에 아래 주소를 복사해 붙여 넣으세요.

   **https://immersive-web.github.io/webxr-samples/hit-test.html**

2. 페이지의 **START AR** 버튼을 누르세요. 카메라나 AR 사용 권한을 묻는 창이 나오면 허용하세요. 버튼이 없거나 **AR NOT FOUND**가 보이면 그 문구를 그대로 알려 주세요.
3. 카메라 화면이 나오면 밝은 방에서 **바닥**을 비추세요. 휴대폰을 좌우로 조금씩, 천천히 움직이며 10~20초 정도 살펴보세요. 화면에 표면을 따라 움직이는 작은 표식이 나타나는지 확인하세요. 화면을 누르면 꽃 모형이 놓일 수 있지만, 이번 확인에서는 누르지 않아도 됩니다.
4. 같은 자리에서 휴대폰을 천천히 위로 기울여 **천장**을 비추세요. 표식이 천장에도 나타나는지 확인하세요. 조명 자체를 정면으로 비추기보다 무늬나 경계가 있는 천장 부분을 살펴보세요. 보이지 않으면 “천장 표식 없음”으로 남기면 됩니다.
5. 확인하는 동안 휴대폰을 접었다 펴지 말고 같은 상태로 유지하세요. 끝나면 Chrome의 뒤로 가기 또는 AR 종료 기능으로 나오세요.

주변을 직접 보면서 안전한 자리에 서서 확인하세요. 천장에 가까이 가기 위해 의자나 사다리에 올라갈 필요는 없습니다.

## 안 열릴 때

- **AR NOT FOUND / START AR 비활성화:** Play 스토어에서 Chrome과 **Google Play Services for AR**의 업데이트가 있는지 확인한 뒤 Chrome에서 링크를 다시 여세요. 설치 또는 업데이트를 요구하는 안내가 뜨면 그 내용을 알려 주세요.
- **권한 거부:** Chrome 주소창 옆 사이트 설정에서 해당 사이트의 카메라·AR 관련 권한을 확인하세요. 권한 이름은 Chrome 버전에 따라 다를 수 있습니다.
- **카메라 화면은 나오지만 표식이 없음:** 방을 밝게 하고, 무늬 있는 바닥을 천천히 살펴보세요. 단색·반사 표면은 인식이 어려울 수 있습니다. 카메라가 나오는 것과 표면 위치를 알아내는 것은 별도 기능입니다.
- **다른 오류:** 화면에 나온 오류 문구를 그대로 보내 주세요. 설정을 계속 바꿀 필요는 없습니다.

## 알려 주실 결과

### 이번 확인에서 카메라가 열리지 않은 경우

사용자는 처음 `START AR`을 누르고 권한도 허용했지만 카메라 화면이 열리지 않았다고 보고했습니다. 이후 독립된 Chrome 앱으로 열도록 안내한 뒤 기본 예제의 실제 카메라 화면이 나온다고 확인했습니다. 초기 실패 원인을 모든 브라우저에 일반화하지 않습니다.

다음 공식 기본 예제는 표면 인식 기능을 요청하지 않아 문제를 분리하는 데 도움이 됩니다.

**https://immersive-web.github.io/webxr-samples/immersive-ar-session.html**

Chrome에서 열어 `START AR`을 누른 뒤 **실제 방의 카메라 영상이 배경에 나오는지** 확인합니다. 시작 전에도 우주·행성 모형이 나올 수 있으므로 행성만 보이는 것은 성공이 아닙니다. 결과는 “실제 방이 보임 / 우주 화면 그대로 / 검은 화면 또는 오류”로 알려 주면 됩니다.

**사용자 확인 결과:** 처음에는 우주 화면 그대로였으나, 화면 캡처에 앱 내부 브라우저로 보이는 × 버튼이 있었습니다. 독립된 Chrome 앱으로 열도록 안내한 뒤 실제 카메라 화면이 나온다고 확인했습니다. 기본 AR 실행 확인은 완료했으며, 실내 바닥·천장 표면 인식은 아직 확인하지 않았습니다.

여기서도 실제 방이 보이지 않으면 [Google Play AR 서비스](https://play.google.com/store/apps/details?id=com.google.ar.core)의 설치·업데이트·활성화 여부와 Chrome 업데이트를 우선 확인합니다. 설치·업데이트 안내가 있는 경우 진행한 뒤 Chrome을 다시 열어 한 번 재시도합니다. 설치형 측정 앱으로 전환하는 절차는 아닙니다.

공식 예제는 일부 오류를 콘솔이나 버튼 설명에만 남겨 휴대폰에서 이유가 보이지 않을 수 있습니다. 사용자에게 개발자 콘솔이나 코드를 요구하지 않습니다.

아래에서 해당하는 내용을 짧게 보내 주시면 됩니다.

```text
START AR 버튼: 보임 / 없음 / AR NOT FOUND
AR 시작 후 카메라 화면: 나옴 / 안 나옴
바닥 표식: 보임 / 안 보임
천장 표식: 보임 / 안 보임
오류 문구: 없음 / 표시된 문구
Android 버전: 알면 기재, 모르면 생략
```

표식이 보였다는 결과는 해당 환경에서 표면 인식 신호가 나왔다는 뜻입니다. 바닥과 천장 사이 높이를 정확하게 측정했다는 뜻은 아닙니다. 천장 표식이 보이지 않는 경우도 숨기거나 임의의 높이로 대체하지 않습니다.

## 공개 범위와 비용

사용자 승인에 따라 소스코드와 정적 앱 파일을 GitHub에 공개했습니다. 기본 GitHub Pages 주소의 정적 호스팅 비용은 0원이며, 카메라 영상은 업로드하지 않습니다. [배포 결과](https-plan.md)에 공개 주소와 검증 근거가 있습니다. 수정 후 실제 휴대폰의 바닥·천장 지정 성공과 정확도 확인은 아직 남아 있습니다.

## 확인 근거

- [Google의 WebXR 실행 조건](https://developers.google.com/ar/develop/webxr/requirements): HTTPS 또는 localhost와 호환 기기·브라우저, 활성화된 Google Play Services for AR 필요.
- [ARCore 지원 기기](https://developers.google.com/ar/devices): Galaxy Z Fold7 등재. 이 목록만으로 실제 방의 천장 인식이나 측정 정확도가 보장되지는 않음.
- [공식 예제 소스](https://github.com/immersive-web/webxr-samples/blob/5d1b7460d1e924797b8c34c72f34fc399f55336f/hit-test.html): 실행 페이지를 2026-11-07에 읽어 **START AR**, **AR NOT FOUND** 문구 확인. 표식 색은 안내의 판단 기준으로 사용하지 않음.
