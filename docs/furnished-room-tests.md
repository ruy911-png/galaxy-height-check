기존 75개와 합쳐 **7개 테스트 파일, 95개 통과**. TypeScript와 Vite 빌드도 통과했습니다. 이미 통과한 17개를 새 오류 수정의 TDD 증거로 보고하지 않습니다. 실패를 먼저 확인한 3개는 안내와 의미 전달 문제이며, 새로운 카메라 인식 알고리즘의 성공 증거가 아닙니다.

추가 Chromium 검사에서는 실제 React/CSS와 모의 AR 엔진으로 320×568, 390×844, 768×800, 844×390 화면을 실행했습니다. 긴 천장 안내가 조준점과 버튼을 가리지 않았고, 잘못된 면의 차단·정상 두 지점 지정·결과 흐름이 통과했습니다. Android 카메라·WebXR 센서는 실행하지 않았습니다.

## 테스트가 확인한 한계

WebXR hit에는 이 면이 침대인지 바닥인지, 문틀인지 천장인지 알려 주는 이름이 없습니다. 수평이고 카메라보다 아래인 침대 윗면은 바닥 후보와 같은 조건을 만족할 수 있습니다. 카메라 위의 수평 문틀 아랫면도 천장 후보와 같은 조건을 만족할 수 있습니다.

합성 좌표로 실제 바닥 0m, 천장 2.4m를 가정했을 때 침대 윗면 0.6m를 잘못 바닥으로 지정하면 결과는 1.8m입니다. 2.1m의 문틀을 천장으로 지정하면 2.1m가 나옵니다. 이 숫자는 계산 한계를 설명하는 테스트 입력이며 실제 방 측정값이 아닙니다. 앱은 두 지정 면의 수직 차이를 계산했을 뿐, 방 전체 높이를 알아낸 것이 아닙니다.

따라서 화면의 “바닥/천장 위치를 인식했어요”를 “지정 가능한 면이에요”로 바꾸고 실제 바닥·천장을 사용자가 확인하도록 안내했습니다. 문구 변경만으로 가구 자동 구별 기능이 생긴 것은 아닙니다. 기울기·좌표 신선도·동일 좌표계 조건을 완화하거나 가까운 면을 건너뛰어 먼 면을 택하지 않았습니다.

## 실제 방에서 남은 확인

| 항목 | 현재 근거 |
| --- | --- |
| 바닥 지정 | 사용자 사진의 ‘02 / 천장 지정’ 화면으로 단계 진행 확인 |
| 천장 지정 | 기울어진 면으로 판단되어 실패한 화면 확인. 성공 미확인 |
| 침대 주변·창가·문 쪽 각각의 카메라 인식 | 장소별 성공/실패 실측 기록 없음. 위 자동 검사는 합성 프레임 검사 |
| 높이 정확도 | 기준 높이·5회 실측 없음, 미검증 |

가구를 치우도록 요구하지 않습니다. [휴대폰 안내](phone-check.md)의 장소별 조작을 따르고, 성공하지 않은 항목은 그대로 실패로 기록해야 합니다. [기준 높이 비교](accuracy-check.md)는 실제 천장 지정과 결과 표시가 된 뒤 진행합니다.
