# 실제 높이 비교 기록

현재 정확도는 **미검증**입니다. 실제 기준 높이와 휴대폰 측정값을 아직 받지 않았습니다. 목표는 “대략적인 높이 확인용”이며, 몇 cm 이내여야 한다는 수치 기준은 아직 정하지 않았습니다.

사용자 요청에 따라 현재 v0.4.0을 대략적인 높이 확인용으로 확정하며 이 검증은 진행하지 않습니다. 아래 내용과 기록표는 나중에 원할 때 사용할 선택 자료이며 사용이나 완료를 위한 필수 절차가 아닙니다.

## 원할 때 추가 검증하는 방법

1. 한 위치를 정하고, 그 위치의 바닥부터 천장까지 **수직 높이**를 줄자 등으로 확인합니다. 비스듬한 길이를 기준값으로 쓰지 않습니다.
2. 앱에서도 같은 바닥·천장 위치를 겨냥합니다. 천장이 기울었거나 단차가 있으면 다른 위치의 높이와 비교하지 않습니다.
3. 한 번 측정한 뒤 결과를 적고, **재측정**을 눌러 처음부터 다시 측정합니다. 같은 위치와 조명에서 총 **5회 시도**합니다.
4. 인식 실패나 추적 중단으로 결과가 없으면 “실패”와 화면의 안내를 적습니다. 실패한 시도를 지우거나 성공할 때까지 바꿔 채우지 않습니다.
5. 가능하면 다른 위치 또는 다른 조명에서도 별도의 5회 기록을 만듭니다. 위치가 바뀌면 그곳의 기준 높이를 다시 확인합니다.

추가 시도를 했다면 별도 행이나 별도 표에 기록합니다. 최초 5회의 실패 횟수는 그대로 남깁니다.

## 기록표

[CSV 기록표](accuracy-record.csv)를 사용하거나 아래 표에 적어도 됩니다. 실제 값은 모두 비워 두었습니다. 높이는 **cm**로 기록하고, 앱에서 m로 보인다면 단위도 함께 보내 주세요.

| 시도 | 위치 | 조명 | 기준 높이(cm) | 앱 측정값(cm) | 성공/실패 | 실패 안내·메모 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | | | | | | |
| 2 | | | | | | |
| 3 | | | | | | |
| 4 | | | | | | |
| 5 | | | | | | |

CSV의 열 이름은 순서대로 `trial`(시도), `location`(위치), `lighting`(조명), `reference_height_cm`(기준 높이), `measured_height_cm`(앱 측정값), `success_or_failure`(성공/실패), `failure_note`(안내·메모)입니다. 실패한 행은 앱 측정값을 비워 두며 **0을 입력하지 않습니다**.

## 결과 정리 방법

같은 위치·조명의 기록끼리 정리하며, 성공한 측정값만 수치 통계에 사용합니다. 실패 횟수는 별도로 보고합니다.

| 항목 | 계산·해석 |
| --- | --- |
| 각 측정의 차이 | 앱 측정값 − 기준 높이. 양수면 실제보다 높게, 음수면 낮게 측정한 것입니다. |
| 평균 차이 | 성공한 각 측정의 차이를 모두 더한 뒤 성공 횟수로 나눕니다. 양수·음수가 상쇄될 수 있으므로 이 값만으로 정확성을 판단하지 않습니다. |
| 가장 큰 절대 차이 | 각 차이에서 부호를 뺀 값 중 가장 큰 값입니다. 기준값에서 가장 많이 벗어난 정도를 보여 줍니다. |
| 반복 측정 범위 | 같은 위치·조명에서 성공한 앱 측정값의 최댓값 − 최솟값입니다. 성공이 2회 미만이면 반복성을 판단하기 어렵다고 표시합니다. |
| 실패 횟수 | 최초 5회 시도 중 실패한 횟수입니다. 실패를 0cm로 계산하거나 통계에서 빠졌다는 이유로 기록에서 지우지 않습니다. |

성공한 측정이 없으면 평균 차이·가장 큰 절대 차이·반복 측정 범위는 계산하지 않습니다. 기준 높이가 없으면 기준값과의 차이는 계산할 수 없습니다. 반복값이 서로 비슷하더라도 모두 같은 방향으로 틀릴 수 있으므로, 반복성과 기준값과의 차이는 구분합니다.

현재는 수치 허용 오차가 합의되지 않아 “허용 오차 통과”로 판정하지 않습니다. 필요해지면 몇 cm 이내여야 하는지와 실패 허용 기준을 정한 뒤 결과와 비교합니다. 기준 높이와 실제 휴대폰 측정 기록을 받기 전에는 정확도를 **미검증**으로 유지하며, 자동 검사 통과를 실측 정확도 검증으로 대신하지 않습니다.
