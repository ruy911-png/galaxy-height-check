# 기준점→상단 높이 측정 — v0.4.0

## 원본 사용 흐름과 구현 범위

사용자가 GitHub 참고 앱의 원래 기능으로 구현하도록 요청하여 기본 흐름을 **바닥 기준점 지정 → 위로 기울여 상단 지정 → 높이 결과 → 다시 측정**으로 변경했습니다. 두 점을 한 화면에 담거나 줌아웃할 필요가 없습니다. 실제 카메라 줌·초광각 선택 기능을 추가한 것은 아닙니다.

원본 `Saicharantejapudi/web-armeasure-`의 Height 모드는 밑부분을 `Place Point`로 저장하고 위로 조준하여 다시 확정합니다. README에는 가상 수직면 계산이 설명되어 있습니다. 원본 코드를 그대로 복사하지 않았으며, 이전 좌표 재사용·결과 출처 미구분 등의 결함도 재현하지 않습니다.

## 두 종류의 상단 위치

**표면 인식 높이:** 현재 화면 중앙에서 가장 가까운 실제 plane hit가 있으면 그 Y 좌표를 사용합니다. 상단에는 수평면 조건을 요구하지 않아 벽의 상단점도 지정할 수 있습니다. `상단.y - 기준점.y`가 결과이며, XZ 이동이나 두 점의 대각선 거리는 높이가 아닙니다.

**추정 높이:** hit-test 결과가 실제로 비어 있고 새 휴대폰 위치·방향 추적이 유효할 때만 추정합니다. 기준점 `B`를 저장한 순간 카메라 위치 `C0`와 B의 수평 방향으로 법선 `n`을 정합니다. 가정한 수직면은 `n·(P-B)=0`이고 n의 Y 성분은 0입니다. 현재 카메라 위치 C와 정규화 조준 방향 d의 교차는 `t=n·(B-C)/(n·d)`, `P=C+t·d`입니다. 이 면은 기준점 저장 후 카메라 이동에 맞춰 임의로 돌아가지 않습니다.

상단이 이 가상 수직면에 있다는 가정이 필요합니다. 벽을 정면으로 보고 벽 바로 앞 바닥과 같은 벽의 천장 경계를 조준하도록 안내합니다. 가구 앞 기준점과 뒤쪽 벽 상단처럼 깊이가 다르거나 벽을 비스듬히 보면 틀릴 수 있습니다. 직접 표면이 없는 상황에서 실제 대상의 깊이를 알아낸 것은 아닙니다. 미리보기와 결과 모두 **추정 높이**를 명시합니다.

## 여러 프레임 중간값 (v0.4.1 이후, 미배포)

버튼을 누른 한 프레임만 쓰면 손떨림과 누르는 순간의 흔들림이 그대로 결과에 들어갑니다. 기준점과 상단 모두 지정 직전 400ms 안의 프레임을 모아 중간값을 사용합니다.

- 최소 3개 프레임이 있고, 그중 60% 이상이 중간값에서 3cm 이내일 때만 적용합니다. 조준이 아직 움직이는 중이면 누른 프레임을 그대로 씁니다.
- 기준점은 위치 전체(x·y·z), 상단은 높이(y)만 중간값을 씁니다. 모서리 근처에서 벽 hit와 천장 hit는 옆으로 떨어져 있기 때문입니다.
- 표면 인식 hit와 가상면 추정은 서로 섞지 않습니다. 세션·좌표계가 바뀌거나 초기화되면 모은 프레임을 버립니다.
- 결과의 `smoothedFrames`가 사용한 프레임 수이며, 2 이상이면 결과 화면에 안내합니다.
- 400ms·3cm·60%는 실측으로 정한 값이 아닙니다. 이 보정은 프레임 사이의 흔들림만 줄이며, 가상 수직면 가정이나 AR 추적 자체의 치우친 오차는 줄이지 못합니다. 정확도는 계속 **미검증**입니다.

## 실패와 초기화

- 기준점은 실제 plane hit만 사용하며 수평에서 20도 이내, 카메라 아래여야 합니다. 카메라 바로 아래 지점처럼 수평 거리가 20cm 미만이면 추정면 방향이 불안정해 다른 기준점을 안내합니다. 이 검사만으로 가구와 바닥을 자동 식별하지는 못합니다.
- 현재 XRFrame의 광선, hit 시각·세션·epoch·viewerY가 일치해야 합니다. 광선은 실제 XRView 투영과 view→viewer 변환으로 화면 중앙에 맞추고, 같은 local-floor 좌표계로 옮깁니다.
- `hitState=none`과 `invalid`를 분리합니다. 잘못된 가까운 hit나 높이가 낮은 hit를 무시하고 가상면으로 우회하지 않습니다. 유효한 새 hit가 있을 때 과거 hit를 대신 사용하지 않습니다.
- 250ms가 지난 현재 프레임, 미래 시각, 비정상 카메라 위치·방향, 추적 상실, 숨김, 좌표계 변경, 새 세션은 기준점과 미리보기를 무효화합니다. 잘못된 상단 hit는 확정을 막지만 유효한 기준점은 보존합니다. 진짜 no-hit이지만 추적이 유지되는 경우에는 저장한 기준점과 새 광선으로 추정할 수 있습니다.
- 평행에 가까운 광선(`|n·d|<0.1`), 카메라 뒤쪽 교차, 30m 초과 교차, 기준점보다 높지 않은 상단은 차단합니다. 이 수치는 수치 오류를 막기 위한 조건이며 정확도 허용 오차가 아닙니다.
- 버튼을 누르는 순간 현재 프레임을 다시 읽어 검사합니다. 화면에 전에 활성 버튼이 남아 있어도 오래된 결과를 확정하지 않습니다.
- 시야 재구성 중에는 좌표를 제공하지 않으며 이전 요청이 늦게 끝나도 새 측정에 섞지 않습니다. 브라우저 화면 확대·이동도 차단합니다.
- 완성된 결과는 세션을 닫은 뒤 과거 기록으로 표시합니다. 재측정하면 결과·기준점·가상면을 모두 지우고 새 세션을 시작합니다.

## 검증과 남은 것

TDD는 합성된 좌표·투영 행렬·XRFrame과 모의 AR을 사용하는 React/브라우저 검사입니다. 카메라 영상은 테스트에 제공하지 않았고 시뮬레이션 값을 프로덕션 측정값으로 사용하지 않습니다.

실제 갤럭시의 v0.4.0 동작, 상단 조준 편의성, 표면 인식과 추정 결과의 오차는 아직 확인하지 않았습니다. 줄자 기준 높이 및 같은 위치 5회 결과를 받아야 정확도를 평가할 수 있습니다. 실제 정확도는 **미검증**입니다.
