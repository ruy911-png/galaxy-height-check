# v0.2.3 검증 기록 — 호환 확인과 최소 높이 측정

확인일: 2026-11-07. 범위: 카메라·WebXR·표면 인식 진단, 수직 높이 계산, 바닥→천장→결과→재측정. 실제 방 높이 정확도 검증은 포함하지 않습니다.

## 작업 환경과 기존 파일

- 최초 작업 폴더에는 기존 프로젝트 코드나 유효한 Git 저장소가 없었습니다. 확인 명령 `git status --short --branch`는 `not a git repository`를 반환했습니다.
- 새 프로젝트 폴더를 만들어 작업했습니다. 기존 사용자 파일을 덮어쓰지 않았습니다.
- Node.js 24.22.1, npm 11.9.0. React 19.3.1, React DOM 19.3.1, Three.js 0.187.0을 설치하고 의존성 잠금 파일을 생성했습니다.
- 초기에는 커밋·푸시·외부 공개·결제를 수행하지 않았습니다. 이후 사용자가 `ruy911-png/galaxy-height-check` 공개 저장소 생성·코드 커밋·푸시·GitHub Pages 배포를 명시적으로 승인했습니다. 유료 결제는 승인 범위에 없으며 사용하지 않습니다.

## 알려진 제한과 다음 검증

- 기본 AR 예제는 독립된 Chrome 앱에서 실제 카메라 화면으로 전환됐다고 사용자가 확인했습니다. 최초 실패와 실행 창의 차이가 관찰됐으나, 모든 앱 내부 브라우저가 WebXR을 지원하지 않는다는 뜻이나 원인 확정으로 확대하지 않습니다. 이후 휴대폰 확인은 링크를 다시 누르는 대신 Chrome 주소창에 URL을 직접 붙여 넣어 진행합니다.
- API의 표면 교차 신호가 실제 천장 재질·정확한 표면 위치를 보증하지 않습니다. 무늬 없는 천장, 조도, 반사, 손떨림에 영향을 받을 수 있습니다.
- DOM overlay와 local-floor를 필수 요청하므로, 단순 AR만 가능한 브라우저는 이 진단을 거부할 수 있습니다. 오류를 지원 성공으로 바꾸지 않습니다.
- 250ms 기준은 오래된 좌표를 차단하는 구현 기준입니다. cm 단위 오차 기준이나 센서 정확도 보장이 아닙니다.
- 수직 높이·대각선 거리 구분, cm/m 변환, 바닥→천장→결과→재측정 상태 검사는 코드 수준에서 완료했습니다. 자체 앱은 사용자 휴대폰에서 바닥 지정과 천장 단계 진입까지 확인했으며, 천장 지정·결과 표시는 아직 미검증입니다.
- 수평면에서 20도 이내, 카메라 높이보다 5cm 넘게 아래/위인 후보만 지정 가능하게 했습니다. 이는 벽이나 반대 방향을 잘못 선택하는 것을 줄이는 조건이지, 바닥·천장의 자동 의미 인식이나 오차 보장이 아닙니다.
- 가상 평면 fallback·앵커 보정은 사용하지 않습니다. 플랫폼이 별도 reset 없이 천천히 좌표를 보정하는 드리프트는 현재 차단 규칙으로 모두 감지할 수 없습니다.
- 실측을 받은 뒤 기준값 오차, 반복 편차, 실패 횟수를 별도로 정리합니다. 설치형 앱으로 임의 전환하지 않습니다.

## v0.2.1 바닥 지정 불편 수정

사용자 보고: 초록 원은 보이지만 바닥 지정이 안 되고 전체화면 안내가 아래 버튼을 가림. 원은 평면 hit 표시이고 바닥 유효성까지 보증하지 않으므로, 실제 기기 차단 원인은 아직 확정하지 않았습니다.

안내를 화면 위로 분리하고 지정 버튼을 올렸습니다. 실제 확정 검사와 같은 함수에서 차단 이유를 읽어 기울어진 면과 카메라보다 낮지 않은 면을 구분합니다. 조건 자체와 오래된 좌표 차단은 유지했습니다.

새 단위 테스트 2개 실패를 확인한 뒤 구현해 전체 71개가 통과했습니다. Chromium 배치 회귀 검사는 4개 크기에서 이전 배치의 하단 간격 실패를 재현하고 수정본의 간격·조준점·클릭·유효/무효 입력·긴 안내를 확인했습니다. 실제 React와 CSS를 사용했지만 AR 엔진은 모의했습니다. [TDD 기록](tdd-log.md)에 구체적인 범위와 결과가 있습니다. 실제 휴대폰의 지정 성공과 정확도는 별도 확인해야 합니다.

수정판 공개 배포도 확인했습니다. [v0.2.1 Pages 작업](https://github.com/ruy911-png/galaxy-height-check/actions/runs/42353836567)은 성공했고, 게시 커밋은 `e580c4961a810f847a4c6249d1401e9aa7f480a0`입니다. 공개 HTML·`assets/index-BWQSUugK.js`·`assets/index-Cg5EXKc1.css`가 테스트한 빌드와 바이트 및 SHA-256 기준으로 일치합니다. 공개 주소의 Chromium 검사 5건도 다시 통과했으며 각 화면에서 `v0.2.1` 표시를 확인했습니다. 이 5건 중 1건은 모의 카메라 거부 안내 검사입니다.

## v0.2.2 추적 실패 오인 수정

일반 window RAF 콜백에는 XRFrame이 없는데, 이전 코드는 이를 AR 추적 실패로 처리했습니다. Three.js 0.187.0에서 세션 연결 후 루프를 등록하면 일반 RAF가 다시 시작되는 경로를 확인했습니다. 루프 등록을 세션 연결 앞으로 옮기고 일반 콜백이 실제 XR 후보·epoch·프레임 감시 시각을 변경하지 않도록 수정했습니다.

새 검사 4개를 먼저 실행해 모두 실패하는 것을 확인한 뒤 수정했고, 전체 75개 및 타입·빌드 검사를 통과했습니다. 실제 pose 없음/emulated, 숨김, 좌표계 reset, 오래된 좌표는 계속 차단합니다. 사진의 증상과 부합하는 코드 결함을 재현했으나 수정 후 실제 휴대폰 성공은 별도 확인이 필요합니다. 세부 사항은 [TDD 기록](tdd-log.md)에 있습니다.
