파일: `tests/measurement.test.ts`, `src/measurement.ts`.

1. 알려진 좌표와 상태 전환을 검사하는 테스트 16개 작성.
2. 미구현 모듈 import 실패 확인. 이때 테스트 본문은 실행되지 않았으므로 동작 실패 수로 세지 않음.

4. 수직 Y 차이·단위·현재 후보 만료·동일 좌표계·추적 무효화·재측정을 구현: **16개 통과**.

명령: `npm test -- tests/measurement.test.ts`.

예: 두 점의 수직 차이 2.4m, 수평 이격 1.8m이면 대각선은 3m이지만 표시할 높이는 2.4m. 모든 숫자는 합성 테스트 입력이며 실측이 아닙니다.

3. 실제 확정과 동일한 검사 함수에서 이유를 읽어 화면에 표시하도록 수정. 유효한 바닥으로 이동하면 버튼이 다시 활성화되고 천장 단계로 넘어가는 것도 검사합니다.
4. 같은 테스트 **13개 통과**. 전체 **7개 파일, 71개 통과**, 타입 검사·빌드 통과.

바닥·천장의 기울기·높이·좌표 신선도 조건을 완화하지 않았습니다. 버튼을 올리고 긴 안내와 버튼의 위치를 분리한 배치 변경은 별도 Chromium 회귀 검사로 검증하며, 위 두 단위 테스트가 실제 휴대폰 터치나 높이 정확도를 증명하지는 않습니다.

### 배치 회귀 검사 — 모의 AR 엔진과 실제 Chromium

구현 전 실패 확인은 위 2개 단위 테스트에 해당합니다. 배치 변경은 이후 별도 하네스로 이전 커밋과 수정본을 비교했으며, 이를 사전에 작성한 TDD라고 확대하지 않습니다.

- 실제 `MeasurementPanel`과 CSS를 사용하고 AR 엔진만 모의했습니다. 모의 데이터는 배포 파일에 포함하지 않습니다.
- 320×568, 390×844, 768×800, 844×390에서 이전 배치는 하단 간격 기준을 모두 충족하지 못했습니다(세로 66px, 가로 29px). 320×568에서는 안내판이 중앙 조준점도 가렸습니다.
- 수정본의 버튼 하단 간격은 세로 125px, 가로 83px로 모두 통과했습니다. 중앙 조준점을 가리지 않고 실제 클릭이 버튼에 도달했습니다.
- 유효한 바닥 클릭 → 천장 단계, 유효하지 않은 벽 클릭 차단, 긴 안내에도 버튼 위치 유지, 실행 오류 없음도 네 크기에서 확인했습니다.
- 실제 Android의 전체화면 시스템 메시지나 WebXR 하드웨어는 이 검사에서 실행하지 않았습니다. 사용자 휴대폰 재확인이 필요합니다.

## v0.2.2 — 일반 화면 갱신을 AR 추적 상실로 오인한 오류

사용자 사진에 초록 원이 표시되어 있지만 추적 실패 안내와 비활성화된 바닥 버튼이 함께 나타났습니다. 이 증상과 부합하는 앱 오류를 코드와 회귀 테스트에서 확인했습니다. 실제 기기의 모든 실패 원인이 이것뿐이라고 확정하지는 않습니다.

근거: 고정한 Three.js 0.187.0의 `WebGLRenderer.setAnimationLoop(callback)`은 일반 window RAF도 시작합니다. `WebXRManager.setSession`의 `sessionstart`가 이를 중지하지만, 앱은 이전에 세션 연결 완료 후 `setAnimationLoop`를 호출해 일반 루프를 다시 시작할 수 있었습니다. 일반 콜백에는 XRFrame이 없는데 앱은 이를 추적 실패로 처리하고 기존 바닥과 현재 후보를 지웠습니다. 일반 콜백이 AR 프레임 감시 시각까지 갱신하는 문제도 있었습니다.

1. 구현 전에 `tests/arMeasurementHit.test.ts`에 4개 회귀 테스트를 추가했습니다: 세션 연결 전 루프 등록, XR 사이의 일반 콜백이 정상 후보·epoch·표시를 지우지 않음, 일반 콜백이 실제 XR 프레임 중단을 숨기지 않음, 일반 콜백이 계속돼도 감시 타이머가 오래된 좌표를 차단함.
2. 실제 실행: **새 4개 실패, 기존 15개 통과**. 정상 후보가 null로 지워지고, XR 중단 알림이 누락되는 실패를 확인했습니다.
3. 루프를 세션 연결 전에 등록하고, XRFrame 없는 일반 콜백은 시각 갱신·무효화·렌더링 전에 반환하도록 수정했습니다.
4. 같은 검사 **19개 통과**. 실제 XRFrame의 viewer pose가 없거나 emulated인 경우는 계속 거부합니다. 250ms 신선도 검사도 완화하지 않았습니다.

이는 합성 프레임으로 실행한 앱/라이브러리 연결 계약 검사입니다. 수정 후 실제 갤럭시에서 바닥→천장 지정을 재확인해야 하며, 실측 정확도는 미검증입니다.

최종 `npm test` 결과는 **7개 파일, 75개 통과**이며 `npm run build`의 타입 검사와 Vite 빌드도 통과했습니다.

## v0.4.0 — 원본 Height 흐름으로 변경

사용자 요청에 따라 한 화면 자동 계산 대신 **바닥 기준점 → 위로 조준 → 상단 지정 → 결과**를 기본으로 구현했습니다. 원본의 가상 수직면 개념을 적용하되 표면 인식값과 추정값을 구분하고, 오래된 hit 재사용은 도입하지 않았습니다.
