# 높이 보기 — 갤럭시 수직 높이 측정 시험용 v0.2.2

갤럭시 Android Chrome에서 바닥과 천장을 지정해 수직 높이를 확인하는 React 웹앱입니다. **바닥 지정 → 천장 지정 → m/cm 결과 → 재측정**을 구현했습니다. 실제 방 높이 정확도는 **미검증**이며 줄자 대체를 보장하지 않습니다.

사용자의 “폴더7”을 우선 Galaxy Z Fold7로 해석했습니다. 사용자 확인 One UI 버전은 **9.0**입니다. 목표는 대략적인 높이 확인이며 2cm·5cm 정확도 기준에 합의한 것은 아닙니다. Android·Chrome 버전과 실제 모델명은 아직 확정하지 않았으며, One UI 버전만으로 Android 버전을 추정하지 않습니다.

## 휴대폰에서 할 일

사용자의 사진과 응답으로 **독립된 Chrome 앱에서 공식 기본 AR 예제의 실제 카메라 표시**를 확인했습니다. 초기에는 야외에 있어 실내 천장 표면 인식과 높이 실측을 보류했습니다. 행성 모형이 나온 사진은 바닥·천장 인식의 증거가 아닙니다.

**앱 주소: https://ruy911-png.github.io/galaxy-height-check/**

무료 GitHub Pages 공개 배포를 완료했습니다. Chrome 앱을 직접 열고 위 주소를 주소창에 붙여 넣으세요. 실내에서 **높이 측정 시작 → 바닥 지정 → 천장 지정** 순서로 확인합니다. 원이 보이지 않거나 버튼이 비활성화되면 화면 안내를 따라 주세요. [휴대폰 안내](docs/phone-check.md)에 자세한 동작이 있습니다.

소스는 [공개 GitHub 저장소](https://github.com/ruy911-png/galaxy-height-check)에 있습니다. HTTPS 응답과 실제 Chromium의 공개 화면 검사는 통과했습니다. 사용자 휴대폰에서 초록 원과 추적 실패 안내가 함께 나타나는 사진을 확인했습니다. v0.2.1의 버튼 배치 개선에 이어 v0.2.2에서는 일반 화면 갱신 신호를 AR 추적 실패로 잘못 처리하는 오류를 수정했습니다. 실제 지정 성공과 높이 정확도는 재확인이 필요합니다.

코드 작성·설치·테스트는 담당 에이전트가 처리합니다. 사용자는 코드를 실행할 필요가 없습니다.

## 구현 범위

- 같은 `local-floor` 좌표계에서 바닥·천장을 기록하고 `천장.y - 바닥.y`로 중력 방향의 높이를 계산합니다. 대각선 거리와 수평 이격 거리를 높이로 쓰지 않습니다.
- 실제 plane hit만 사용합니다. 가상 평면 fallback, 입력하지 않은 기준 높이, 시연용 측정값은 없습니다.
- 바닥은 카메라 아래, 천장은 카메라 위에 있어야 하며 수평에서 20도 이내인 면만 후보로 받습니다. 이 필터가 표면의 실제 종류를 자동 판별하는 것은 아니므로 사용자가 실제 바닥·천장에 원을 맞춰야 합니다.
- 추적이 계속되는 동안 바닥 기록은 유지하고, 현재 천장 후보만 새 위치인지 검사합니다. 추적 상실·화면 숨김·프레임 중단·좌표계 변경·세션 교체 시 바닥부터 다시 시작합니다.
- 결과는 m/cm로 표시합니다. 정상 완료 후 닫힌 AR 세션의 결과는 과거 기록으로만 남으며 재측정을 누르면 이전 높이·좌표를 지우고 새 세션을 시작합니다.
- HTTPS/보안 문맥, WebXR AR 지원 응답, 별도 카메라 영상, 실제 AR 평면 hit-test를 구분합니다.
- React로 한글 안내와 큰 버튼을 표시하고 Three.js로 실제 WebXR 표면 표식을 그립니다.
- 카메라는 사용자 버튼으로만 시작하며 마이크를 요청하지 않습니다. AR 시작 전 미리보기 스트림을 중지합니다.
- 영상 업로드, 로그인, 광고, 분석 수집, 서버 API, 유료 측정 API, 런타임 외부 CDN이 없습니다.
- `local-floor`, `hit-test`, `dom-overlay` 기능이 모두 필요합니다. 기본 AR 지원 응답만으로 이 기능의 성공을 판정하지 않습니다.
- 현재 프레임에 실제 plane hit가 없으면 확인을 막습니다. 250ms를 넘긴 좌표, 추적 상실, 화면 숨김, 좌표계 reset, 세션 종료 시 이전 hit를 사용할 수 없습니다.
- 별도 진단 화면의 바닥·천장 체크는 **사용자가 향한 방향의 표면 신호 기록**입니다. 이 체크만으로 높이를 계산하지 않습니다.
- 화면의 ‘확인 기록 복사’는 텍스트를 휴대폰 클립보드에 복사할 뿐 전송하지 않습니다. 브라우저 종류를 포함하며 영상·사진·좌표는 포함하지 않습니다.

## 개발 실행 방법

Node.js 24.22.1 / npm 11.9.0에서 설치·검사합니다. 앱과 개발 의존성 버전은 `package.json`, 간접 의존성은 `package-lock.json`에 고정했습니다.

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run dev
```

`npm run dev`가 표시하는 localhost 주소는 해당 컴퓨터의 개발용입니다. 휴대폰에서 컴퓨터의 일반 `http://192.168…` 주소를 여는 방식은 WebXR의 보안 조건을 충족하지 않습니다. 휴대폰이 신뢰하는 HTTPS 주소로 **최상위 페이지에서 직접** 열어야 합니다. iframe 미리보기는 권한 정책에 따라 거절될 수 있습니다.

프로덕션 파일은 `dist/`에 생성됩니다. HTTPS 정적 호스팅만 필요하며 서버 연산이나 비밀 키는 필요 없습니다. GitHub의 `main`에는 소스, `gh-pages`에는 검증한 정적 빌드가 있습니다. `public/_headers`는 Cloudflare Pages·Netlify 형식이며 GitHub Pages에는 적용되지 않습니다. 공개 HTTPS 응답은 확인했고 실제 휴대폰 카메라·AR 동작은 별도로 확인해야 합니다.

## 다음 단계

초기 v0.1 진단 구현은 엄밀한 TDD가 아니었습니다. v0.2 높이 측정은 테스트 작성 → 실제 실패 확인 → 구현 → 통과 확인 순서로 진행했습니다.

1. 실내에서 자체 앱의 실제 바닥·천장 인식과 측정 흐름을 확인합니다. 공개 배포와 Chromium 화면 검사는 완료했으며 실제 휴대폰 WebXR 검사는 남아 있습니다.
2. 줄자 기준 높이와 5회 반복 측정의 차이·편차·실패 횟수를 기록합니다. 실측을 받기 전 정확도는 미검증입니다.
3. 실측 후 화면을 다듬고 결과 저장을 추가합니다. 결과 저장 기능은 아직 구현하지 않았습니다.

사용자는 이 저장소의 소스코드 공개 커밋·푸시와 무료 GitHub Pages 공개 배포를 명시적으로 승인했습니다. 유료 서비스·결제는 사용하지 않습니다. 추가 공개 범위나 유료 작업은 별도 지시 없이 진행하지 않습니다.
