# 높이 보기 — 기준점에서 위로 높이 측정 v0.4.1

갤럭시 Android Chrome에서 **바닥 기준점 지정 → 휴대폰을 위로 기울임 → 상단 지정 → 높이 결과** 순서로 사용하는 React 웹앱입니다. 참고 앱의 Height 사용 흐름으로 변경했습니다. 바닥과 천장을 한 화면에 동시에 담을 필요는 없습니다.

앱: https://ruy911-png.github.io/galaxy-height-check/

소스: https://github.com/ruy911-png/galaxy-height-check

v0.4.0에서 사용자가 확정한 측정 방식을 유지하고, v0.4.1에서 점검 도구를 기본 접힘으로 정리했습니다. 추가 줄자 비교나 반복 측정을 완료 조건으로 요구하지 않습니다.

## 휴대폰에서 할 일

1. Chrome 앱에서 주소를 열고 새로고침해 **v0.4.1**을 확인합니다.
2. **높이 측정 시작**을 누르고 권한을 허용합니다.
3. 벽을 정면으로 보고, 벽 바로 앞의 실제 바닥에 중앙 표시를 맞춰 **바닥 기준점 지정**을 누릅니다.
4. 같은 벽을 따라 휴대폰을 천천히 위로 기울여 벽과 천장이 만나는 상단에 중앙 표시를 맞춥니다.
5. 미리보기의 높이와 표시 종류를 확인하고 **상단 지정**을 누릅니다. **다시 측정**하면 새로 시작합니다.

앱 안에도 두 화면 그림과 조작 안내가 있습니다. 빈방일 필요는 없으나 기준점은 가구·침대가 아닌 실제 바닥이어야 합니다. 휴대폰을 바닥이나 천장에 댈 필요가 없습니다.

카메라·AR 점검과 확인 기록 복사는 **문제가 있나요? 점검 도구**를 눌렀을 때만 보입니다. 높이 측정은 펼치지 않고 사용합니다. 점검 도구를 접으면 카메라 미리보기도 종료합니다.

## 두 종류의 결과

- **표면 인식 높이**: 현재 조준한 실제 AR 표면 위치와 저장한 기준점의 수직 차이입니다. 상단은 수평 천장뿐 아니라 벽의 상단점도 지정할 수 있습니다. 사물 종류를 식별하거나 정확도를 보증하는 것은 아닙니다.
- **추정 높이**: 상단의 실제 표면 hit는 없지만 휴대폰 위치·방향 추적이 유효할 때, 바닥 기준점을 지나는 가상 수직면과 현재 조준 방향의 교차점으로 계산합니다. **상단이 그 가상 면 위에 있다고 가정합니다.** 가구 앞 바닥을 기준으로 뒤쪽 벽을 조준하는 등 깊이가 다르면 틀릴 수 있습니다. 실제 천장 표면을 인식한 값과 구분해 표시합니다.

**두 결과 모두 실제 높이 정확도는 미검증**입니다. 사용자는 새 v0.4.0 방식이 동작하는 듯하다고 보고한 뒤 현재 버전을 확정했습니다. 구체적인 결과값·결과 종류·기준 높이는 제공되지 않았으므로 정확도 검증으로 기록하지 않습니다.

## 구현 범위

- 같은 `local-floor` 좌표계에서 `상단.y - 기준점.y`로 수직 높이를 계산합니다. 대각선 거리나 가정한 방 높이는 쓰지 않습니다.
- 기준점은 현재 실제 평면 hit로만 기록합니다. 상단의 새 hit가 있으면 그 위치를 사용하고, 진짜 no-hit일 때만 추정합니다. 잘못된 가까운 hit를 건너뛰거나 이전 hit를 사용하지 않습니다.
- 위치·방향 추적 상실, 250ms 초과 좌표, 화면 숨김, 좌표계 초기화, 새 세션은 기준점과 미리보기를 무효화합니다. 단순히 상단 표면만 안 보이는 상황과 추적 상실은 다르게 처리합니다.
- 추정면은 기준점을 지정할 때 고정됩니다. 평행에 가까운 조준, 카메라 뒤쪽 교차, 과도하게 먼 교차는 차단합니다.
- 현재 표시와 관계없이 버튼을 누르는 순간 좌표를 다시 검사합니다. 완성된 결과는 종료 후 과거 결과로 남으며 재측정 시 지웁니다.
- 실제 카메라 줌·0.5배 초광각 선택 기능은 없습니다. 이 사용 흐름은 두 곳을 한 화면에 담을 것을 요구하지 않습니다. 브라우저 화면 확대는 좌표 대응이 어긋날 수 있어 측정을 막습니다.
- 영상은 휴대폰 안에서 처리하며 업로드·로그인·광고·분석 수집·유료 API·외부 런타임 CDN이 없습니다. 마이크를 요청하지 않습니다.
- 이전 한 화면 자동 계산과 직접 수평 천장 방식은 회귀 검사 코드로 남아 있으며 현재 기본 화면은 기준점→상단 방식입니다.

사용자 기기는 “폴더7”을 우선 Galaxy Z Fold7로 해석했고 One UI 9.0은 사용자 확인 정보입니다. 목표는 대략적인 높이 확인입니다. 코드 작성·검사는 에이전트가 수행하며 사용자는 설치 명령을 실행할 필요가 없습니다.

## 개발 실행 방법

Node.js 24.22.1 / npm 11.9.0에서 설치·검사합니다. 앱과 개발 의존성 버전은 `package.json`, 간접 의존성은 `package-lock.json`에 고정했습니다.

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run dev
```

`npm run dev`가 표시하는 localhost 주소는 해당 컴퓨터의 개발용입니다. 휴대폰에서 컴퓨터의 일반 `http://192.168…` 주소를 여는 방식은 WebXR의 보안 조건을 충족하지 않습니다. 휴대폰이 신뢰하는 HTTPS 주소로 **최상위 페이지에서 직접** 열어야 합니다. iframe 미리보기는 권한 정책에 따라 거절될 수 있습니다.

프로덕션 파일은 `dist/`에 생성됩니다. HTTPS 정적 호스팅만 필요하며 서버 연산이나 비밀 키는 필요 없습니다. GitHub의 `main`에는 소스, `gh-pages`에는 검증한 정적 빌드가 있습니다. `public/_headers`는 Cloudflare Pages·Netlify 형식이며 GitHub Pages에는 적용되지 않습니다. 공개 HTTPS 응답은 확인했고 실제 휴대폰 카메라·AR 동작은 별도로 확인해야 합니다.

## 확정 상태

사용자 요청에 따라 현재 v0.4.1을 인계합니다. 추가 실측이나 결과 저장 등 기능 추가를 완료 조건으로 남기지 않습니다. 기존 5회 기록표와 오차 비교 방법은 나중에 원할 때 사용할 선택 자료입니다. 정확도는 **미검증**으로 유지하며 자동 테스트 통과를 실제 오차 검증으로 해석하지 않습니다.

사용자는 이 저장소의 소스코드 공개 커밋·푸시와 무료 GitHub Pages 공개 배포를 명시적으로 승인했습니다. 추가 공개 대상이나 유료 서비스를 사용하지 않습니다.
